  x86.level.v2 [arch.zon]: x86-64-v2: CMPXCHG16B, LAHF/SAHF, POPCNT, SSE3 to SSE4.2 (Nehalem, Bulldozer and later).
  x86.level.v3 [arch.zon]: x86-64-v3: AVX, AVX2, BMI1/2, F16C, FMA, LZCNT, MOVBE, XSAVE (Haswell, Excavator and later).
  x86.march.v2 [arch.zon]: A kernel built elsewhere (CI) for a CPU no model rule names: the instruction set it has for sure.
  x86.march.v3 [arch.zon]: The same at x86-64-v3.
  x86.efi.early-dma [arch.zon]: efi=disable_early_pci_dma: bus mastering stays off from the EFI stub until the IOMMU is up, closing the window in which a device could write to memory at boot.
  x86.ia32-off [arch.zon]: ia32_emulation=0: no 32-bit syscall entry; the gaming session's own UKI turns it on (docs/principles.md).
  x86.aes [arch.zon]: The disk is AES-XTS: the AES-NI driver built into the machine kernel, not loaded on demand.
  audio.sof.intel [audio.zon]: The audio DSP of Intel laptops (SOF): its firmware and topology files are named at run time; UCM tells PipeWire how to use the digital microphones.
  board.dell.secure-boot [board.zon]: Dell firmware: Expert Key Management.
  cpu.intel.microcode [cpu-intel.zon]: Microcode updates for Intel CPUs, loaded early from the initrd (dracut early_microcode): fixes and mitigations the firmware of the board may lack.
  cpu.intel.kernel [cpu-intel.zon]: The machine kernel's Intel class: intel_pstate, intel_idle, RAPL and the uncore counters, coretemp, the iTCO watchdog.
  cpu.intel.me [cpu-intel.zon]: The Management Engine interface: AMT is not used and the firmware TPM works through tpm_crb; the HECI driver is attack surface without a use here.
  cpu.intel.watchdog [cpu-intel.zon]: The chipset watchdog (iTCO) for optional/deadman; it needs LPC or SMBus to be found.
  cpu.intel.kvm-off [cpu-intel.zon]: VH_VIRT=no: KVM is refused, so a kernel exploit cannot slip a thin hypervisor under the system; disable VT-x in the firmware as well.
  cpu.intel.hybrid [cpu-intel.zon]: P and E cores: the scheduler places tasks by core type and cluster (ITMT, SCHED_CLUSTER); vh-sched reads the topology at load (U4).
  cpu.intel.march.alderlake [cpu-intel.zon]: Alder Lake and Raptor Lake (models 0x97, 0x9A, 0xB7, 0xBA, 0xBF): -march=alderlake.
  gpu.i915 [gpu.zon]: Intel graphics up to Gen12 (Skylake to Raptor Lake, DG2): the i915 driver, VA-API through intel-media-driver (Broadwell and newer [VERIFY] older parts need libva-intel-driver), its firmware in linux-firmware-intel; Vulkan (ANV) in the gaming root.
  gpu.i915.adlp [gpu.zon]: Alder Lake-P and Raptor Lake-P graphics (Iris Xe): the DMC and GuC of ADL-P, the HuC of Tiger Lake [VERIFY on hardware].
  gpu.renderer.gles2 [gpu.zon]: A GPU with a DRM driver: RefursWM renders with GLES2.
  net.wifi [net.zon]: A wireless interface: iwd, the regulatory database (signed, read by cfg80211 from the initrd of a machine kernel), iw for diagnosis, the firmware package of network chips, and the feature wifi, the 802.11 stack of a machine kernel. Without a wireless interface a machine kernel has no such stack, and the stock kernel loads cfg80211 only as a Wi-Fi driver's dependency (rootfs/etc/modprobe.d/vh-cfg80211.conf).
  net.iwlwifi [net.zon]: Intel Wi-Fi: iwlwifi's firmware, one pattern for every generation it names.
  net.iwlwifi.so-gf [net.zon]: Intel Wi-Fi 6E AX211 on the CNVi of Alder/Raptor Lake (the So family with the GF radio): its firmware and PNVM [VERIFY on hardware].
  bt.usb [net.zon]: A Bluetooth controller on USB (interface class E0).
  bt.bluez [net.zon]: Bluetooth present and allowed (VH_BLUETOOTH optional or on): bluez, off until started with vh-bluetooth on (optional) or always running (on).
  bt.intel.kernel [net.zon]: Intel Bluetooth with the bluetooth feature: btusb with the Intel vendor code only.
  bt.intel [net.zon]: Intel Bluetooth (USB vendor 8087): btintel picks its ibt- firmware at run time.
  class.laptop.chassis [platform.zon]: DMI chassis 8 (portable), 9 (laptop), 10 (notebook), 14 (sub-notebook), 30 (tablet), 31 (convertible), 32 (detachable).
  class.laptop.battery [platform.zon]: A battery of the system (not of a peripheral) in a machine that is not virtual.
  class.desktop [platform.zon]: Every other machine.
  class.laptop [platform.zon]: The laptop class: power follows AC and battery, the lid and the backlight are handled.
  iommu.dmar [platform.zon]: VT-d is described by the DMAR table; intel_iommu=on turns it on (Void's kernel leaves it off by default) so that every device's DMA is translated.
  acpi.lid [platform.zon]: An ACPI lid switch (PNP0C0D).
  acpi.power-button [platform.zon]: An ACPI power button (PNP0C0C, or the fixed LNXPWRBN).
  acpi.power-button.tiny-off [platform.zon]: tiny_power_button and button both match a control-method power button (PNP0C0C), and the first to load wins; tiny_power_button provides no input device, so vh-acpid would never see the button (found on the test bench, kernel 6.18.57).
  acpid.lid [platform.zon]: vh-acpid handles the lid (lock, then a regular poweroff; suspend is forbidden) and the power button.
  acpid.button [platform.zon]: vh-acpid handles the power button (a regular poweroff by default).
  input.i8042 [platform.zon]: A PS/2 keyboard (most laptops, virtual machines): the i8042 controller and atkbd built into the machine kernel, so the LUKS passphrase can be typed.
  tpm.tools [platform.zon]: A TPM 2.0: tpm2-tools reads the measurement log (the Option ROM check before key enrolment) and serves tpm2-totp.
  tpm.crb [platform.zon]: A firmware TPM through the Command Response Buffer interface (Intel PTT, AMD fTPM).
  tpm.ftpm.intel [platform.zon]: A TPM through CRB on an Intel machine is Intel PTT, the firmware TPM of the Management Engine [VERIFY: tpm2_getcap properties-fixed names the manufacturer INTC].
  usb.common [platform.zon]: What a USB port must handle after the module lock: storage, keyboards and mice, audio.
  camera.usb [platform.zon]: A USB video device (interface class 0E).
  camera.off [platform.zon]: VH_CAMERA=no: the UVC driver is refused (the firmware setup can disable the camera outright, which is stronger).
  cardreader.off [platform.zon]: VH_CARDREADER=no: the Realtek card reader's drivers are refused.
  watchdog.softdog [platform.zon]: No hardware watchdog known: softdog, which does not survive a hung kernel (a row in the cost table).
  quirk.thunderbolt [quirks.zon]: Thunderbolt and USB4 controllers: the driver stays refused (it tunnels PCIe, that is DMA from a cable); USB and DisplayPort through these ports work without it.
  quirk.fingerprint [quirks.zon]: A fingerprint reader without a kernel driver: libfprint is not installed, logins use passwords.
  storage.nvme [storage.zon]: An NVMe disk: the driver built into the machine kernel (the root disk is behind it before the initrd can load anything).
  storage.vmd [storage.zon]: Intel VMD (the firmware's RAID or RST mode): the NVMe disks sit behind it and are invisible without its driver, so the initrd carries it.
  storage.trim [storage.zon]: A fixed disk that accepts discard and VH_TRIM=yes: fstrim once a week (SSD speed and wear levelling; the cost is that the disk shows which blocks are free).

notes (5):
  Dell: Secure Boot, Expert Key Management, Enable Custom Mode, then Delete All Keys.  <- board.dell.secure-boot
  The TPM is Intel PTT, a firmware TPM inside the Management Engine: trusting tpm2-totp and the measured boot means trusting the ME (docs/03).  <- tpm.ftpm.intel
  Thunderbolt/USB4: the thunderbolt driver is refused; USB devices and displays on these ports work, docks with PCIe devices (a network card) do not.  <- quirk.thunderbolt
  The fingerprint reader is not used: there is no libfprint here, and logins use passwords.  <- quirk.fingerprint
  Intel VMD (RAID/RST mode) is on: Linux reaches the NVMe disk through it. Switching the firmware setup to AHCI mode is simpler, but it changes how an installed Windows boots.  <- storage.vmd
